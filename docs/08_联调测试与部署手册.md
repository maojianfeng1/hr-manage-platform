## 1. 启动前准备（必看，避开 3 个历史坑）

### 坑 1：MySQL 必须先在跑
后端连的是本机 MySQL 8.0.34（`hr_manage` 库，root/123456）。
- 确认 MySQL 服务已启动（任务管理器看 `mysqld.exe`，或 `net start mysql`）。

### 坑 2：Spring Boot 端口被 `SERVER__PORT` 劫持
你本机 shell 注入过 `SERVER__PORT=0`，Spring Boot 宽松绑定会认成 `server.port=0` → 起在**随机端口**，前端代理 8080 就连不上。
- **IDEA 启动**：在 Run/Debug Configuration 的 **Environment variables** 加 `SERVER__PORT=8080`（或直接删掉这个变量）。
- **命令行启动**：先 `unset SERVER__PORT`（Git Bash）后再跑。

### 坑 3：前端命令必须在 `frontend/` 子目录
根目录没有 `package.json`，在根目录跑 `npm run dev` 会 `ENOENT`。必须 `cd` 进 `frontend/`。

## 2. 启动后端（8080）

### 方式 A：IDEA（推荐，你一直这么用）
1. 打开 `E:\java-web\hr-manage-platform\backend`。
2. 右上角 Run 配置选 `HrManageServerApplication`（主类）。
3. **确认 Environment variables 已处理坑 2**（加 `SERVER__PORT=8080`）。
4. 点 ▶ 启动。
5. **验证节点**：控制台出现 `Started HrManageServerApplication in ...` 且末尾无报错；浏览器开 `http://localhost:8080/api/health` 返回 `{"code":200,...}` 即成功。

### 方式 B：Maven 命令行（备用）
```bash
# Git Bash，先 unset 坑 2
unset SERVER__PORT
cd /e/java-web/hr-manage-platform/backend
"D:/jdk/bin/java" \
  -classpath "D:/develop/apache-maven/apache-maven-3.9.4/boot/plexus-classworlds-2.7.0.jar" \
  -Dclassworlds.conf="D:/develop/apache-maven/apache-maven-3.9.4/bin/m2.conf" \
  -Dmaven.home="D:/develop/apache-maven/apache-maven-3.9.4" \
  -Dmaven.multiModuleProjectDirectory="E:/java-web/hr-manage-platform/backend" \
  org.codehaus.plexus.classworlds.launcher.Launcher \
  -s "D:/develop/apache-maven/apache-maven-3.9.4/conf/settings.xml" \
  -Dmaven.repo.local="D:/develop/apache-maven/apache-maven-3.9.4/mvn_repo" \
  -f "E:/java-web/hr-manage-platform/backend/pom.xml" \
  spring-boot:run
```

> 8080 若报 `Address already in use`：先杀占用进程
> ```bash
> # 查占用
> netstat -ano | findstr :8080
> # 杀掉对应 PID（替换下面的 12345）
> taskkill /PID 12345 /F
> ```

## 5. 测试用例清单（交付物之一）

> 覆盖正常 / 边界 / 异常。每一项是「操作 → 预期结果」。

### 5.1 认证与权限
| 用例 | 操作 | 预期 |
|------|------|------|
| 登录-正常 | admin/123456 | 200，返回 token + 菜单树 |
| 登录-密码错 | admin/000000 | 401 或业务码失败 |
| 无 token 访问 | 不带 Authorization 调 `/api/employee/page` | 401 拦截 |
| 越权访问 | employee 调 `/api/employee/page` | 403 拦截 |
| 菜单动态 | hr 登录 | 菜单不含系统管理 |
| 刷新保活 | 任意登录后 F5 | 不丢登录态、菜单不闪 |

### 5.2 部门 / 岗位
| 用例 | 操作 | 预期 |
|------|------|------|
| 部门-新增 | 填名称提交 | 列表新增成功 |
| 部门-重名 | 同名下再建 | 业务提示（或成功，看实现） |
| 部门-删除 | 删除有下属员工的部门 | 逻辑删除成功（员工记录不受影响） |
| 岗位-新增 | 选部门+填名称 | 成功 |

### 5.3 员工 / 考勤 / 薪酬
| 用例 | 操作 | 预期 |
|------|------|------|
| 员工-新增不传 gender | 新增时不选性别 | 后端补默认 1，不 500 |
| 考勤-新增不传 overtime | 加班小时留空 | 后端补 0，不 500 |
| 薪酬-生成工资单 | 有考勤+薪资档案 | 实发 = 应发 - 社保 - 公积金 - 个税，计算正确 |
| 薪酬-同员工同月重复 | 同一人同一月再生成 | 幂等，不重复出单 |

### 5.4 系统管理
| 用例 | 操作 | 预期 |
|------|------|------|
| 用户-新增 | 建 testuser 绑 hr 角色 | 列表出现，能登录 |
| 用户-重置密码 | 重置后登录 | 用新密码可登 |
| 角色-授权菜单 | employee 勾考勤 | 重登后出现考勤菜单 |
| 角色-删自己 | admin 删 admin 角色 | 应拦截或提示，不能自废 |

### 5.5 个人看板（行级权限）
| 用例 | 操作 | 预期 |
|------|------|------|
| employee 看本人 | 登录看板 | 只看到刘道睿本人数据 |

| 未关联员工账号 | 某账号 employee_id 为 NULL 调个人接口 | 返回空或提示「未关联员工档案」 |

## 6. 部署方案（从开发到上线）

### 6.1 后端打包成 jar
```bash
cd /e/java-web/hr-manage-platform/backend
"D:/jdk/bin/java" -classpath "D:/develop/apache-maven/apache-maven-3.9.4/boot/plexus-classworlds-2.7.0.jar" \
  -Dclassworlds.conf="D:/develop/apache-maven/apache-maven-3.9.4/bin/m2.conf" \
  -Dmaven.home="D:/develop/apache-maven/apache-maven-3.9.4" \
  -Dmaven.multiModuleProjectDirectory="E:/java-web/hr-manage-platform/backend" \
  org.codehaus.plexus.classworlds.launcher.Launcher \
  -s "D:/develop/apache-maven/apache-maven-3.9.4/conf/settings.xml" \
  -Dmaven.repo.local="D:/develop/apache-maven/apache-maven-3.9.4/mvn_repo" \
  -f "E:/java-web/hr-manage-platform/backend/pom.xml" \
  clean package -DskipTests
```
- 产物：`backend/target/hr-manage-backend-1.0.0.jar`
- 运行：`java -jar backend/target/hr-manage-backend-1.0.0.jar`（生产建议用 `application-prod.yml` 覆盖端口/数据库/关 swagger）

### 6.2 前端打包成静态资源
```bash
cd E:\java-web\hr-manage-platform\frontend
npm install
npm run build
```
- 产物：`frontend/dist/`（纯静态文件）

### 6.3 Nginx 反向代理（生产推荐）
```nginx
server {
    listen 80;
    server_name hr.example.com;   # 改成你的域名或 localhost

    # 前端静态资源
    location / {
        root  /path/to/frontend/dist;
        try_files $uri $uri/ /index.html;   # 支持 Vue Router history 模式
    }

    # 后端接口转发（替代开发期 Vite 代理）
    location /api {
        proxy_pass http://127.0.0.1:8080;   # 后端 jar 实际地址
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```
- 这样用户只访问 80 端口，浏览器不再有跨域问题，前后端都由 Nginx 统一入口。

### 6.4 生产注意事项
- 数据库密码、JWT 密钥写进 `application-prod.yml`，**不要硬编码进代码**。
- 关掉开发期 swagger / 健康检查对外暴露（视情况）。
- `DataInitializer` 只在库为空时建演示账号，重复启动不会覆盖已有数据。

## 7. 常见启动 / 联调报错速查

| 现象 | 原因 | 解决 |
|------|------|------|
| 后端起在随机端口 / 前端代理 404 | `SERVER__PORT=0` 劫持 | 坑 2：IDEA 配 `SERVER__PORT=8080` 或命令行 `unset` |
| `npm run dev` 报 ENOENT / package.json 不存在 | 在根目录跑 | 坑 3：`cd frontend/` 再跑 |
| 登录后菜单空白 / 一直转圈 | 后端 8080 没起或代理没生效 | 查 `/api/health`；确认前端请求走 5173 代理 |
| 普通员工看板空白、KPI 全 0 | 权限收回后走个人分支但没数据 | 确认 `employee` 账号 `employee_id` 已关联（当前关联刘道睿）；个人接口返回空属正常 |
| 红色「没有操作权限」弹窗 | 调了无权限的公司级接口 | 正常拦截；若想消除，收回对应菜单授权或改静默请求 |
| 端口占用 `Address already in use :8080` | 上次后端没关 | `netstat -ano | findstr :8080` → `taskkill /PID xxx /F` |
| MySQL 连不上 / 库不存在 | MySQL 没起 或 连错库 | 确认连的是 `hr_manage`（非 hrm_db），MySQL 服务在跑 |
