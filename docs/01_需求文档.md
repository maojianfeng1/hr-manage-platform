## 1. 项目背景与目标

### 1.1 背景

中小型企业普遍存在「组织架构靠 Excel、考勤靠纸质签到、算薪靠手工表格」的问题，数据分散且无法联动统计。本平台将组织、员工、考勤、薪酬四条业务线收敛到一个系统内，并通过数据看板为管理者提供人力成本与出勤情况的可视化决策依据。

### 1.2 建设目标

1. **业务闭环**：员工入职建档 → 日常考勤 → 月度算薪 → 数据看板，形成一条完整的人力资源数据链路（不是四个互不相干的 CRUD 页面）。
2. **权限可控**：基于 RBAC 模型实现管理员 / 人事 / 普通员工三角色的数据可见性与操作权限隔离。
3. **技术完整**：覆盖后端分层架构、统一返回与异常处理、JWT 认证、前后端分离、路由/按钮级权限、数据可视化等主流企业级开发范式。
4. **可讲解**：复杂度控制在简历演示级别，每个模块的设计动机与关键代码都能在面试中说清楚。

### 1.3 范围边界（明确不做的事）

> 面试时被问「为什么不做 XX」时，能答出「范围裁剪的主动决策」是加分项。

| 不在本版本范围内 | 原因 |
| --- | --- |
| 审批工作流（请假审批、报销流程） | 需引入工作流引擎，成本高、答辩难，改为「人事直接录入/修改考勤结果」 |
| 排班管理、弹性工时、多班次 | 采用统一标准工时（9:00–18:00），迟到/早退规则固定 |
| 个税专项附加扣除、社保分城市基数 | 采用固定比例 + 简化累进税率演示算法 |
| 文件上传（头像、附件） | 头像使用 URL 字段存储，避免 OSS/文件服务依赖 |
| 多租户、SaaS 化 | 单企业场景，不做数据隔离 |
| 消息队列、分布式、微服务 | 单体架构足够，重点在业务与技术规范 |

## 2. 术语与定义

| 术语 | 说明 |
| --- | --- |
| RBAC | Role-Based Access Control，基于角色的访问控制。用户 → 角色 → 权限（菜单/接口标识） |
| 组织 | 公司的部门（department）与岗位（position）两级结构 |
| 考勤记录 | 员工某一天的出勤结果（正常 / 迟到 / 早退 / 旷工 / 请假 / 加班） |
| 薪资档案 | 员工的薪酬结构：基本工资、岗位工资、绩效工资、社保公积金基数 |
| 工资单（Payroll） | 某员工某个月份的算薪结果明细，由「薪资档案 + 当月考勤」计算生成 |
| 应发工资 | 基本工资 + 岗位工资 + 绩效工资 + 加班费 − 考勤扣款 |
| 实发工资 | 应发工资 − 社保个人 − 公积金个人 − 个人所得税 |

## 3. 用户角色定义

| 角色标识 | 角色名称 | 典型使用者 | 核心诉求 |
| --- | --- | --- | --- |
| `ADMIN` | 系统管理员 | 信息化负责人 | 管账号、管角色权限、管组织架构，可看全部数据 |
| `HR` | 人事专员 | HR 部门员工 | 管员工档案、录考勤、算工资，不碰系统权限配置 |
| `EMPLOYEE` | 普通员工 | 公司员工 | 只看得到自己的信息：个人资料、个人考勤、个人工资条 |

**一个用户只有一个角色**（简化设计，避免多角色合并权限的复杂度）；用户与员工档案通过 `user_id` 关联：**管理员与人事账号可以不绑定员工档案，普通员工账号必须绑定一份员工档案**（否则「我的考勤/我的工资条」无从取数）。

## 5. 详细功能需求

### M1 登录与权限

| 功能点 | 需求描述 |
| --- | --- |
| 登录 | 用户名 + 密码 + 验证码（可选，先用账号密码）登录；密码错误 5 次锁定 10 分钟（可选，本版先记录失败次数不做锁定） |
| Token | 登录成功返回 JWT（有效期 2 小时），前端存 localStorage，每次请求放 `Authorization` 请求头 |
| 获取用户信息 | 登录后根据 token 拉取用户基本信息、角色、可访问菜单树与权限标识集合 |
| 动态菜单 | 前端根据后端返回的菜单树渲染侧边栏（**不是前端写死路由表**），这是本项目的核心亮点之一 |
| 按钮级权限 | 后端返回权限标识数组（如 `employee:add`），前端用 `v-hasPermi` 指令控制按钮显隐；后端接口用注解/拦截器二次校验 |
| 退出登录 | 前端清除 token 与用户信息，跳转登录页（后端可将 token 加入黑名单，本版简化为前端清除） |
| 修改密码 | 校验原密码 → 新密码二次确认 → BCrypt 加密存储 |

**校验规则**：用户名 4–20 位字母数字；密码 6–20 位，存储使用 BCrypt 强哈希（**禁止明文/MD5**）；连续登录失败返回统一错误码。

### M2 系统管理（仅 `ADMIN`）

| 功能点 | 需求描述 |
| --- | --- |
| 用户管理 | 用户列表（分页 + 按用户名/角色/状态筛选）、新增、编辑、重置密码、启用/停用 |
| 角色管理 | 角色列表、角色新增/编辑、为角色分配菜单权限（树形勾选） |
| 约束 | 内置角色 `ADMIN/HR/EMPLOYEE` 不允许删除；停用的用户无法登录 |

### M3 组织管理

| 功能点 | 需求描述 |
| --- | --- |
| 部门管理 | 树形结构展示（支持二级/三级部门），支持新增、重命名、调整上级部门、删除、排序 |
| 部门负责人 | 部门可指定一名负责人（关联员工） |
| 岗位管理 | 岗位隶属部门，字段：岗位名称、岗位编码、编制人数、岗位描述 |
| 删除约束 | 部门下有子部门或仍有在职员工时，禁止删除（返回明确错误提示） |
| 在职人数 | 部门列表展示「在职人数 / 编制人数」，用于看板与人力规划展示 |

### M4 员工管理

| 功能点 | 需求描述 |
| --- | --- |
| 员工档案 | 字段：工号、姓名、性别、手机号、邮箱、身份证号、部门、岗位、职级、入职日期、转正日期、员工状态（试用/在职/离职）、头像 URL |
| 列表查询 | 分页 + 关键字（姓名/工号/手机号）+ 部门筛选 + 状态筛选；支持按入职日期区间筛选 |
| 新增员工 | 工号唯一校验（后端唯一索引兜底）；入职日期不能晚于今天 |
| 编辑员工 | 修改部门/岗位后，历史考勤与工资单仍归属原记录（**工资单快照部门/岗位名称，不做级联更新**） |
| 状态变更 | 转正、离职操作：离职需填写离职日期，离职后不再出现在考勤录入候选列表 |
| 员工详情 | 展示基本信息 + 近 3 个月考勤概览 + 近 6 个月工资趋势（小图） |

### M5 考勤管理

**考勤规则（本版固定，写进需求，代码里做成常量）**

| 规则 | 定义 |
| --- | --- |
| 标准工时 | 上班 09:00，下班 18:00 |
| 正常 | 上班打卡 ≤ 09:00 且下班打卡 ≥ 18:00 |
| 迟到 | 09:00 < 上班打卡 ≤ 12:00 |
| 早退 | 下班打卡 < 18:00 |
| 旷工 | 当天无打卡记录且无请假 |
| 请假 | 事假 / 病假 / 年假（按天计，人事录入） |
| 加班 | 下班打卡 ≥ 20:00 记为加班，计入加班时长 |

| 功能点 | 需求描述 |
| --- | --- |
| 考勤记录 | 以「员工 + 日期」为唯一键；字段：上班打卡时间、下班打卡时间、状态、请假类型、加班时长、备注 |
| 录入方式 | ① 单条新增/编辑；② 批量录入（勾选多人 + 统一日期状态，简化演示）；③ 预留 Excel 导入接口位置（本版实现批量新增即可） |
| 月度汇总 | 按「月份 + 员工」统计：出勤天数、迟到次数、早退次数、旷工天数、请假天数、加班小时数 |
| 考勤查询 | 人事按部门/月份查询全员汇总；员工只看自己的月度汇总与明细 |
| 扣款规则 | 迟到/早退每次扣 50 元；旷工每天扣 日薪 × 2；事假扣日薪；病假扣日薪 × 50%；加班按 日薪/8 × 1.5 × 加班小时 计发 |
| 日薪计算 | 日薪 = (基本工资 + 岗位工资) / 21.75（国家规定月计薪天数） |

### M6 薪酬管理

| 功能点 | 需求描述 |
| --- | --- |
| 薪资档案 | 每名在职员工一份：基本工资、岗位工资、绩效工资、社保基数、公积金基数、银行卡号；支持按员工查询与编辑 |
| 社保公积金 | 个人缴纳比例：养老 8% + 医疗 2% + 失业 0.5% = 10.5%（公积金 7%，合计 17.5%），按基数计算，比例写为配置常量 |
| 个税计算 | 简化累进：应纳税所得额 = 应发 − 5000 − 社保个人 − 公积金个人；≤0 不纳税；≤3000 按 3%；≤12000 按 10%（速算扣除 210）；≤25000 按 20%（速算扣除 1410）；其余按 25%（速算扣除 2660） |
| 工资单生成 | 选择「月份」批量生成：遍历在职员工 → 取薪资档案 → 取当月考勤汇总算扣款 → 生成工资单（**幂等**：同月重复生成先删除旧记录再插入，或提示已生成） |
| 工资单详情 | 展示各项收入、扣款、社保、个税、实发工资；支持单条调整（补发/扣款备注）与删除 |
| 我的工资条 | 员工查看自己的历史工资单，支持按年份筛选 |
| 薪酬统计 | 按月份统计：工资总额、人均工资、部门人力成本分布（看板数据源） |

> **面试可讲的算薪设计点**：① 幂等生成（重复点击不产生脏数据）；② 工资单**快照**员工当时的部门/岗位/姓名，避免档案变更影响历史账目；③ 算薪与考勤解耦，考勤改了重新生成即可。

## 7. 核心业务流程

### 7.1 员工入职建档（M3 + M4）

```
创建部门/岗位 → 新增员工档案（生成工号） → 若需登录权限则创建系统账号并绑定员工 → 建立薪资档案
```

### 7.2 月度算薪主流程（M5 + M6，本项目业务闭环的关键链路）

```
① 人事录入当月考勤（每日记录/批量）
      ↓
② 系统按「月份+员工」生成考勤汇总（出勤/迟到/早退/旷工/请假/加班）
      ↓
③ 选择月份点击「生成工资单」
      ↓
④ 遍历在职员工：取薪资档案 → 取当月考勤汇总 → 计算加班费与扣款
      ↓
⑤ 计算应发 → 扣社保公积金 → 计算个税 → 得实发
      ↓
⑥ 写入工资单（快照部门/岗位/姓名），同月重复生成先清旧数据
      ↓
⑦ 看板读取工资单 → 展示人力成本趋势
```

### 7.3 登录鉴权流程（M1）

```
前端提交用户名密码 → 后端校验（BCrypt 匹配）→ 生成 JWT（含 userId/username）
      ↓
前端存 token，每次请求带 Authorization 头
      ↓
后端拦截器解析 token → 查用户角色 → 查角色权限集合
      ↓
接口上的权限注解 vs 用户权限集合 → 通过则放行，否则 403
      ↓
前端同时用权限集合控制菜单渲染与按钮显隐（体验层），后端做最终校验（安全层）
```

## 9. 非功能需求

| 类型 | 要求 |
| --- | --- |
| 性能 | 列表分页默认 10 条；考勤/工资单批量操作单批 ≤ 500 条；关键查询字段建索引 |
| 安全 | 密码 BCrypt 加密；JWT 签名 + 过期时间；接口权限后端二次校验（不能只依赖前端隐藏按钮）；SQL 全部使用 `#{}` 参数绑定防注入 |
| 易用性 | 统一返回结构 `{code, msg, data}`；统一异常兜底；表单必填校验与错误提示 |
| 兼容性 | 主流 Chrome/Edge；页面最小宽度 1280px |
| 数据规范 | 所有表含 `create_time / update_time / is_deleted`；删除一律逻辑删除 |
| 代码规范 | 后端四层：Controller → Service → Mapper → DB；统一 `Result` 返回；前后端字段命名统一小驼峰 |

## 12. 附录：面试讲解要点（提前准备）

1. **为什么做这个项目**：选题来自中小企业人力管理痛点，四个模块有真实业务闭环（入职→考勤→算薪→看板），能体现业务理解而不只是 CRUD。
2. **技术亮点（挑 4 个讲透）**
   - RBAC 动态权限：菜单与按钮权限由后端下发，前端不写死；接口层用拦截器 + 注解二次鉴权（防止绕过前端篡改）。
   - JWT 无状态登录 + BCrypt 加密：讲清 token 结构、过期续期方案、为什么不用 Session（前后端分离/可扩展性）。
   - 算薪幂等设计：同月重复生成先清后插；工资单快照历史字段，档案变更不影响历史账目。
   - 数据看板聚合查询：一条 SQL group by 出图，讲清为什么用「空间换时间」的月度汇总思路。
3. **难点与解决**：考勤与薪酬的数据一致性（先汇总考勤再算薪）、权限矩阵落地（前后端双层校验）、联调中的跨域与 token 失效处理。
4. **可拓展方向**：接入工作流引擎做请假审批、考勤数据改由 Excel/钉钉导入、引入 Redis 缓存菜单权限与字典、算薪改异步任务 + 消息队列。
