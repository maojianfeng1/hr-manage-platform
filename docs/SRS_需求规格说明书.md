# 人力资源管理服务平台 需求规格说明书

> 版本：V1.0  
> 文档类型：软件需求规格说明书（SRS）  
> 适用对象：系统设计、开发、测试、验收及利益相关方

---

## 1. 引言

### 1.1 编写目的
本文档定义"人力资源管理服务平台"（项目代号：`hr-manage-platform`）的功能需求、非功能需求与运行环境约束，作为系统设计、编码实现、测试验证与项目验收的统一依据。

### 1.2 项目背景
企事业单位的人力资源管理工作普遍面临数据分散、流程线下、统计滞后等问题。本系统面向中小型组织，提供一套覆盖**组织架构、人事档案、考勤记录、薪酬核算、数据决策**的人力资源信息化解决方案，实现核心人事业务的线上化、规范化与可视化。

### 1.3 术语与缩略语

| 术语 | 说明 |
|---|---|
| RBAC | 基于角色的访问控制（Role-Based Access Control），系统权限模型核心 |
| JWT | JSON Web Token，无状态鉴权令牌（HS256） |
| 逻辑删除 | 以 `is_deleted` 标记记录失效，不物理删除数据 |
| 行级权限 | 数据访问按当前登录用户身份过滤，用户仅可访问归属自身的数据 |
| 看板 | 基于 ECharts 的数据可视化驾驶舱页面 |

## 2. 总体描述

### 2.1 产品定位
本系统是一套 B/S 架构的中小企业人力资源管理平台，包含后台管理（Spring Boot + MyBatis）与前端控制台（Vue 3 + Element Plus）。系统以"组织—人事—考勤—薪酬—决策"为主线，支持多角色协同办公。

### 2.2 用户角色与权限模型

系统采用 RBAC 三级权限模型（用户—角色—权限），内置三类角色：

| 角色标识 | 角色名称 | 职责范围 | 典型权限 |
|---|---|---|---|
| `admin` | 系统管理员 | 系统全部配置与业务管理 | 用户/角色/菜单管理 + 全部业务模块 |
| `hr` | 人事专员 | 组织与人事业务全流程 | 组织/员工/考勤/薪酬管理，不含系统级配置 |
| `employee` | 普通员工 | 个人相关信息查询 | 数据看板 + 个人中心（行级权限，仅本人数据） |

权限判定由后端 `@RequiresPermission` 注解拦截器与前端 `hasPerm` 双重控制：无权限的菜单与操作在前端不渲染，在后端拦截返回 403，形成前后端双保险。

### 2.3 运行环境

| 项 | 后端 | 前端 |
|---|---|---|
| 运行环境 | JDK 21、Spring Boot 3.2 | Node.js 18+、Vue 3 |
| 数据库 | MySQL 8.0.34 | — |
| 构建部署 | Maven、Docker | Vite、Nginx |
| 浏览器 | — | Chrome / Edge 等现代浏览器 |

## 3. 功能需求

### 3.1 系统管理
面向系统管理员，负责平台基础配置与权限治理。

- **用户管理**：系统账号的增删改查、启用/停用、登录信息维护、密码重置。
- **角色管理**：角色的增删改查，并为角色分配菜单与按钮权限（授权即勾选权限标识）。
- **菜单管理**：维护系统菜单树（目录/菜单/按钮三级），配置路由、组件、图标与权限标识，作为权限分配的载体。

### 3.2 组织管理
支撑企业组织结构建模。

- **部门管理**：部门信息维护，支持树形多级部门（`parent_id` 自关联）、部门编码、负责人与排序。
- **岗位管理**：岗位信息维护，岗位隶属部门，支持编制人数（headcount）管理。

### 3.3 员工管理
系统业务主数据。

- **员工档案**：维护员工工号、姓名、性别、联系方式、证件、部门/岗位、职级、入职/转正日期、学历、工资卡号、住址等全量人事信息，支持分页查询与增删改。

### 3.4 考勤管理
记录员工日常出勤。

- **考勤记录**：按"员工 + 日期"维度记录上班/下班打卡时间、考勤状态（正常/迟到/早退/旷工/请假/加班）、请假类型与加班时长，支持录入与修正。

### 3.5 薪酬管理
薪酬核算与发放。

- **薪资档案**：为每位员工建立薪资档案，含基本工资、岗位工资、绩效工资、社保基数、公积金基数与工资卡号。
- **工资单**：按"员工 + 发薪月份"生成工资单，自动汇总应发工资、社保/公积金个人部分、个人所得税与实发工资，支持生成与作废。

### 3.6 数据看板
面向管理决策的驾驶舱（ECharts 可视化）。

- **全员视图**：具备业务权限的用户可见组织人员结构、考勤统计、薪酬分布等聚合分析结果。
- **个人视图**：普通员工进入看板时自动切换为个人视图，仅展示本人考勤与薪酬概览（行级权限）。

### 3.7 个人中心（普通员工）
为普通员工提供个人数据自助查询，全部接口基于行级权限，员工仅可访问本人数据：

- **我的信息**：查看本人档案。
- **我的考勤**：查看本人考勤记录。
- **我的工资**：查看本人工资单。

## 4. 非功能需求

| 类别 | 需求说明 |
|---|---|
| 性能 | 常规列表查询接口响应时间 < 500ms（万级数据量）；看板聚合查询 < 1s |
| 安全性 | 密码 BCrypt 哈希存储；JWT 无状态鉴权；接口级权限拦截；敏感接口（个人数据）行级权限；统一全局异常处理，不泄露堆栈 |
| 兼容性 | 前端兼容 Chrome / Edge 等现代浏览器（ES2018+）；后端兼容 MySQL 8.0 |
| 可用性 | 关键业务数据逻辑删除，支持恢复；登录失败有限流与日志审计 |
| 可维护性 | 前后端分离、分层架构；统一响应封装；权限以声明式注解管理，新增接口无需硬编码鉴权逻辑 |
| 可扩展性 | 菜单/角色权限可配置，无需改代码即可调整角色能力；预留数据字典、操作日志等扩展点 |

## 5. 验收准则

1. 三类角色可正常登录并进入授权范围内的功能页面。
2. 无权限的菜单/按钮在前端不可见，直接调用对应接口返回 403。
3. 普通员工通过个人中心接口无法查询到他人档案/考勤/薪酬。
4. 各业务模块增删改查闭环可用，逻辑删除生效，数据看板正常渲染。
5. 系统在 MySQL 8.0 + JDK 21 环境下可稳定启动并通过端到端联调。
