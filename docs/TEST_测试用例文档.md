# 人力资源管理服务平台 测试用例文档

> 版本：V1.0  
> 测试类型：功能测试 / 接口测试 / 权限与越权测试 / 异常测试  
> 环境：JDK 21 + MySQL 8.0 + Spring Boot 3.2 + Vue 3

---

## 1. 测试策略

| 测试类型 | 目标 | 方法 |
|---|---|---|
| 功能测试 | 验证各角色可完成业务闭环 | 前端 UI 操作 + 后端接口联调 |
| 接口测试 | 验证接口正确性与鉴权 | 自动化/手动请求，校验状态码与返回体 |
| 权限测试 | 验证 RBAC 前后端双控 | 无权限菜单不渲染 + 直接调用返回 403 |
| 越权测试 | 验证行级数据权限 | 普通员工尝试访问他人数据 |
| 异常测试 | 验证参数校验与全局异常 | 非法参数、边界值 |

**测试账号**：`admin / 123456`、`hr / 123456`、`employee / 123456`

## 3. 接口与权限测试用例

### 3.1 鉴权与权限拦截
| 编号 | 接口 | 角色 | 预期 |
|---|---|---|---|
| I-01 | `POST /api/auth/login` | 任意 | 返回 token |
| I-02 | `GET /api/system/user/page` | 无 token | 401 |
| I-03 | `GET /api/system/user/page` | employee | **403**（无 system:user:view） |
| I-04 | `GET /api/system/user/page` | admin | 200，返回分页数据 |
| I-05 | `GET /api/menu/user-menus` | employee | 200，仅含看板菜单 |
| I-06 | 直接访问无权限前端路由 | employee | 前端守卫拦截，不渲染 |

### 3.2 行级越权测试（重点）
> 普通员工（`employee`）通过 `UserContext.empId` 仅可访问本人数据；下列接口对 employee 角色做归属校验。

| 编号 | 接口 | 操作 | 预期 |
|---|---|---|---|
| I-07 | `GET /api/employee/{他人id}` | employee 调用 | **业务异常，拒绝访问**（非本人） |
| I-08 | `GET /api/attendance/{他人id}` | employee 调用 | **业务异常，拒绝访问** |
| I-09 | `GET /api/salary/standard/{他人id}` | employee 调用 | **业务异常，拒绝访问** |
| I-10 | `GET /api/salary/payroll/{他人id}` | employee 调用 | **业务异常，拒绝访问** |
| I-11 | `GET /api/personal/my-info` | employee 调用 | 200，仅返回本人档案 |
| I-12 | 上述接口 | admin / hr 调用 | 200，不受归属限制（selfId 为空） |

### 3.3 分页与查询
| 编号 | 接口 | 预期 |
|---|---|---|
| I-13 | 各 `/page` 接口 | 返回 records + total，分页正确 |
| I-14 | 列表查询带条件 | 按条件过滤正确 |

## 4. 边界与异常测试

| 编号 | 用例 | 步骤 | 预期 |
|---|---|---|---|
| B-01 | 重复考勤 | 同一员工同一天再次录入 | 唯一约束拦截，提示重复 |
| B-02 | 重复工资单 | 同员工同月份再次生成 | 唯一约束拦截 |
| B-03 | 删除带子节点的菜单 | 删除含子项菜单 | 校验失败，提示先清理子节点 |
| B-04 | 非法参数 | 缺必填字段提交 | 400，返回字段级错误 |
| B-05 | 逻辑删除 | 删除员工/用户 | `is_deleted=1`，列表不展示但数据可恢复 |
| B-06 | 服务健康 | `GET /api/health` | 200，用于部署探针 |

## 5. 测试结论

| 项 | 结论 |
|---|---|
| 三角色登录与导航 | 通过，权限隔离符合 RBAC 设计 |
| 业务模块 CRUD | 通过，逻辑删除生效 |
| 接口鉴权与 403 拦截 | 通过，前后端双控一致 |
| 行级越权防护 | 通过，employee 无法访问他人敏感数据 |
| 边界与异常 | 通过，唯一约束与全局异常正常 |

**遗留/建议**：
1. 生产环境应将数据库密码改为环境变量注入，避免配置文件明文（本项目已采用 `${DB_PASSWORD:123456}` 占位符）。
2. 建议补充操作日志 AOP 切面与数据字典模块，进一步提升审计能力与可配置性。
3. 高并发场景下建议对菜单、字典类数据引入缓存（如 Redis）。
